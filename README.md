# 搭子 · Dazi

> 你的工作搭子。把事情交给它，它接着推进；你回来时，心里有数。

搭子是一个本地优先的桌面 AI 工作伙伴。它不是又一个聊天框，而是围绕「一项工作」持续推进的同事：记得这项工作的来龙去脉，在你不在的时候继续干活，需要你拍板时才来找你。

## 为什么做搭子

大多数 AI 工具的交互是这样的：

```text
想起一件事 → 打开 AI → 重新交代背景 → 等回答 → 自己把结果搬回工作里
```

搭子想要的是：

```text
交代一次 → 它持续推进、记住进展 → 只在需要决定时打扰你 → 你回来时看到结果和下一步
```

用户不应该为了使用 AI，先去做一大堆管理 AI 的工作。

## 产品立场

1. **以工作为中心。** 一项「工作」是唯一的一等对象：目标、目录、对话、产物、决策和进度都挂在它下面。没有散落各处的会话、模式和功能页。
2. **打开先看简报，而不是空白输入框。** 首页回答三个问题：什么在等我决定？我不在时推进了什么？下一步建议做什么？
3. **它记住，你纠正。** 每项工作有一份自动维护的「工作档案」（决策、约定、踩过的坑）。用户只在它记错时修改，不需要手动整理记忆。
4. **说结果，不说过程。** 先给结论和需要你做的事，执行细节折叠起来，想看时随时展开。
5. **只在该打扰时打扰。** 对外发送、不可逆操作需要你确认；其余在工作目录内的事情它自己处理。
6. **不掉棒。** 关掉窗口、重启电脑、断网，进行中的工作都会从断点接着跑。

## 第一版做什么

只打磨一条黄金路径：

```text
新建工作（目标 + 目录）
  → 交代任务，搭子开始推进
  → 你离开；它在后台继续，或按计划定时推进
  → 中途崩溃 / 重启，从断点续跑
  → 你回来，简报告诉你：等你决定的、已经完成的、建议的下一步
  → 一键批准，产物交付，工作档案自动更新
```

## 第一版不做什么

本地模型推理、IM 渠道接入、多主题与外观设置、外接编程 Agent 工作台、企业管理后台、插件市场、团队协作、移动端。

这些不是永远不做，而是在黄金路径足够好之前，一律不做。

## 状态

Agent 接入分支保留已验收的水彩界面，并加入 Electron 桌面壳和唯一持久化工作进程。桌面模式使用真实 Pi Durable：输入、取消、工具审批、工作档案与定时规则保存在本机 SQLite。浏览器模式仍是明确标注的内存演示，刷新会重置。

实现与验证边界见 [Agent 接入记录](docs/agent-integration.md)。受控官方协议回放不是在线模型验收；真实供应商 API 冒烟仍需用户本机安全配置凭据后执行。

## 运行

Node 24.22.0（与 Electron 内置版本一致），Bun 1.4.3。

```sh
bun install --frozen-lockfile
bun run dev        # 浏览器 UI 演示
bun run desktop    # 构建并启动真实桌面应用
```

桌面应用只在 Host 读取供应商环境配置。用户在本机安全配置 OPENAI_API_KEY 或 ANTHROPIC_API_KEY 后，从继承该环境的终端启动应用；能力页只显示可用状态并选择模型。不要把密钥贴进聊天、源码或测试。此版本不提供应用内凭据保存或登录流程。

支持系统托盘时，关闭窗口会收起到托盘，工作继续；从托盘退出会安全关闭存储。没有可用托盘时，关闭最后窗口会退出应用，下一次启动再恢复。重新启动恢复已保存工作。模型/工具故障保留原生终态；不把所有闲置状态当作成功。定时使用电脑本地时间，每周一执行；首次启用不会补跑启用前任务，离线后只补最近一次错过的槽位。

```sh
bun run typecheck
bun run lint
bun run format:check
bun run test
bun run build
bun run test:e2e
bun run build:desktop
bun run test:electron
```

浏览器测试需要 Playwright Chromium；Linux Electron 测试需要显示服务（CI 使用 xvfb）。CI 上传实际截图与报告，不部署。Electron 测试显式启用受控模型，只在临时目录操作，不使用真实凭据。
